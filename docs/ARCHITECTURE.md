# Архитектура hix

    +--------------------------------------------------------------+
    |  qubix: shell, процессы, VFS, tty, syscalls (int 0x80)         |
    +-----------------------------+--------------------------------+
    |  aether: task/thread, scheduler, ports/IPC, vm, heap           |  steel
    +-----------------------------+--------------------------------+  (графика)
    |  drivers: vga, bga, pci, serial, pit, rtc, ps2 kbd/mouse       |
    +--------------------------------------------------------------+
    |  hix core: boot, GDT/TSS/IDT/PIC, traps, printk, panic        |
    +--------------------------------------------------------------+

## Загрузка (`kernel/main.c`)
GDT/IDT/PIC → консоли (serial + steel) → `pmm_init` → `vm_init` (страничная
память) → `kalloc_init` → `task_init`/`sched_init` (загрузочный контекст становится
потоком `idle`) → драйверы → `qubix_init` → поток `init` → `init` (pid 1) → `sh`.

## aether
- **pmm** — битовая карта страниц, непрерывные выделения.
- **vm** — страницы 4 КиБ: страница 0 не отображена (NULL → фолт), `.text/.rodata`
  только для чтения, у каждого стека потока — guard-страница. Переполнение
  стека ловит double-fault на отдельном TSS-стеке и печатает диагноз.
- **kalloc** — куча с граничными тегами, magic-проверки, double free = panic.
- **task/thread/sched** — задача = контейнер ресурсов (порты), поток = исполнение;
  round-robin с квантом 50 мс, вытеснение на выходе из прерывания, `ctx_switch` в
  `arch/x86/switch.asm`. Блокировки: `spin_lock_irqsave` (короткие) и `mutex`
  (длинные); ожидание — `waitq_wait_irq`.
- **ipc** — порты с правами SEND/RECEIVE, имена с «поколением», сообщения с
  reply-портом, таймауты, bootstrap-сервис имён (`hix.upper` в демо).

## qubix
- Один `int 0x80`: положительные номера — вызовы процессов (`write`=4,
  `wait4`=7, `ioctl`=54 …), отрицательные — порты aether (`AE_*`, например
  `ae_msg_trap`=-31), `steelctl`=500.
- `proc` = оболочка над `task`: pid, fd-таблица, `wait4`, зомби.
- tty имеет сырой режим (`ioctl`), на нём построен редактор строки шелла.
- Программы (`qubix/progs.c`, `shell.c`) используют только `libq.h` — то есть
  syscalls; когда появится ring 3, они переедут без переписывания.
- `sysctlbyname` отдаёт текст: `kern.*`, `hw.*`, `hix.ps`, `hix.devtree`, `hix.dmesg`.

## steel
`steel_device` → `steel_surface` → `steel_cmdbuf` (записал команды — `commit`) →
`steel_layer` + композитор → консоль с ANSI-цветами и прокруткой.

Два бэкенда: VGA-текст и **пиксельный** (`gfxdev`/`pixdev`). Драйвер `bga`
находит адаптер Bochs VBE по PCI, ставит 1024x768x32, фреймбуфер берёт из BAR0
(он попадает в существующие некэшируемые 4-МБ страницы). `pixdev` рисует клетки
80x25 гладким шрифтом 12x28 и подставляет вместо «дырок» (`STEEL_HOLE`)
холсты зарегистрированных клиентов. `canvas`/`gfx.h` — ARGB-холст: заливка,
скруглённые прямоугольники, текст, блиттинг с альфой. Курсор мыши рисуется ядром
с сохранением фона, программам код курсора не нужен.

## desk
Рабочий стол — процесс qubix (`apps/`, `include/desk/`). События от клавиатуры и
мыши (`qubix/input.h`) приходят через `steelctl(STEEL_CTL_EVENT)`, готовый кадр
уходит через `STEEL_CTL_PRESENT`; пока desk держит экран, консоль приостановлена.
Программы — таблица `struct app` (`apps/desk_apps.c`), у каждого окна своя
поверхность и 8 КБ приватной памяти, так что аллокатор не нужен. Пиксельная
программа (Chess) владеет холстом и регистрирует его в steel; события мыши
приходят с точностью до пикселя. Backend
(`struct desk_backend`) подменяется в тестах скриптом событий.
