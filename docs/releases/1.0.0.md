# hix 1.0.0 — hi is not unix

The first public release after `0.3.4`. This is not "another intermediate
version": `1.0.0` locks down the boot experience, host-side configuration, the
ring 3 ABI and the build/verification process that can now be promised to
users.

Screenshots: `docs/screenshots/` in the repository and in the source archive.

## Download

- `hix.elf` — kernel for QEMU with `-kernel` (Multiboot).
- `hix.iso` — bootable image with a GRUB menu.
- `hix-1.0.0-src.tar.gz` — sources.
- `SHA256SUMS` — checksums of the three files above.

Download everything into one directory and verify:

    sha256sum -c SHA256SUMS
    qemu-system-i386 -m 128M -cdrom hix.iso

Checking the ELF:

    qemu-system-i386 -m 128M -kernel hix.elf -serial stdio

## Highlights

### A boot experience that does not scare

- A splash screen with a wide block logo (CP437 half-blocks, equally sharp in
  VGA text and pixel mode), a large UTC clock, date, RAM, Rust crypto module
  status and a progress bar. Any key skips it.
- `quiet = on` removes info/notice from VGA, but `dmesg` and COM1 remain
  complete. This matters for debugging: the screen is clean, the log has not
  gone anywhere.
- Four screensavers — `stars`, `matrix`, `clock`, `blank` — are ordinary
  qprog programs, not kernel code. They start manually and after idle, and
  preserve an unsubmitted shell line.
- `splash`, `quiet`, `screensaver`, `screensaver_timeout` are set in
  `config/hix.conf` via `scripts/hixctl` or overridden for one boot:
  `hix.splash=4`, `hix.quiet=0`, `hix.screensaver=matrix`, `hix.timeout=60`,
  `hix.safe=1`.
- The GRUB menu has five entries: normal, verbose, no splash, safe mode and
  serial console on COM1 115200. COM1 is a full shell, not just a log.

### Stable interfaces

- One `int 0x80` for qubix programs and ring 3: files, directories, processes,
  time, sysctl, sleep, `SYS_gantry` and `SYS_crypto`.
- `libhix` for ring 3: `hx_printf` (`%s %c %d %u %x`, width, `0` and `-`),
  files, `spawn/wait`, `hx_readdir`, `hx_sysctl`, `hx_crypto`.
- `SYS_gantry` (600): Kit services `kit.system`, `kit.prop`, `kit.notify`.
  Fixed service name parsing: `kitinfo` sees `kit.system` again.
- The Rust crypto module remains optional for a normal build, but the release
  build requires it and verifies it in three ways: crate unit tests, Python
  vectors and `cryptotest` from ring 3.

### System

- aether: pages, heap, threads, round-robin, wait queues, ports and IPC.
- qubix: processes, in-memory VFS, tty, shell with history/Tab/redirection,
  `desk`, `splash`, `screensaver`.
- steel: VGA text and 1024x768x32 pixel mode (Bochs VBE), Argent theme,
  panels, cursor, canvases, chess with full rules.
- Gantry: device registry, driver model, Kit and tweaks in C++.
- ring 3: separate address space, ELF loader, pointer validation, demo
  programs and the SDK.

### Release engineering

- `include/hix/version.h` is the only source of the version.
- `make version`, `make verify`, `make smoke`, `make release`.
- `make verify`: style, Multiboot, host tests (including the 32-bit scheduler
  and uspace), Rust, Python vectors and desktop frame comparison.
- `make release`: clean strict build, full `verify`, QEMU smoke,
  `dist/hix-1.0.0/` with ELF/ISO/docs/logs, `BUILD-INFO` and `SHA256SUMS`.
- CI (GitHub Actions): build, tests, Rust, ISO and smoke on every push/PR.
- Added `LICENSE` (GPL-2.0-only), `CONTRIBUTING.md`, `SECURITY.md`,
  `docs/INSTALL.md`, `docs/RELEASE.md`, `docs/VERSIONING.md`.

## Fixes included in this release

- `GANTRY_LOOKUP` read the service name from the wrong argument — `kitinfo`
  got `kit.system not found (-14)`.
- `hx_printf` did not support `%-12s`: the unknown flag shifted arguments,
  `lsbin` dereferenced the file size and crashed in ring 3.
- Smoke test: a race when connecting serial/monitor, loss of the first bytes,
  incorrect handling of `socket.timeout` and too early return from
  `screensaver` — fixed; the test now checks splash, screensaver and the full
  set of commands.
- `parse_seconds` no longer substitutes the maximum on garbage input: an
  unknown `hix.*` value is ignored instead of changing boot behavior.

## Verified

- `make STRICT=1 RUST=1 all` — no warnings.
- `make verify` — all host tests, Rust, crypto and 34 frames.
- `python3 scripts/smoke.py --require-rust` — boot, splash, `uname`,
  `crypto`, `sysctl hix.crypto`, `progs`, `kitinfo`, `lsbin`, `fstest`,
  `cryptotest`, `hixfetch`, screensaver, `halt`.
- The ISO was booted separately in QEMU via GRUB: menu, `hix.elf` and `uname -a`.
- Kernel: about 218 KiB of `.text` with the Rust module.

## Known limitations

- No installation to disk, disk filesystem, SMP, users or access permissions.
- The VFS lives in memory: files in `/tmp` disappear after a reboot.
- There is no guest bash: qubix uses its own shell; the bash layer lives on
  the host in `scripts/hixctl`.
- The full set of desktop scenarios is not run automatically in QEMU; frames
  and logic are checked by host tests.
- Pixel mode requires Bochs VBE (QEMU `-vga std`, Bochs, VirtualBox).
  On other hardware the 80x25 text mode remains.

## Upgrading from 0.3.4

The version skipped over local `0.3.5`–`0.6.1`, so the changelog should be read
as a single list of changes. Configuration now lives in `config/hix.conf`; the
old hard-coded splash/quiet values are replaced by `scripts/hixctl` and
`hix.*` parameters. A build without Rust still works, but the release ISO is
built with the crypto module.
