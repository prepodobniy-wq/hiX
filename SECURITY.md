# Безопасность

## Что поддерживается

| Версия | Статус |
|---|---|
| 1.0.x | поддерживается |
| 0.x | не поддерживается; обновитесь до 1.0.0 |

hix — учебное/исследовательское ядро для i386, а не продукт для защиты
данных. У него нет пользователей, прав доступа, дискового шифрования и
сетевого стека. Не используйте его как единственную защиту для чего-то
ценного.

## Как сообщить об уязвимости

Если проблема может затронуть других пользователей (побег из ring 3,
повреждение памяти ядра, обход проверки указателей, ошибка в
`SYS_crypto`), **не открывайте публичный issue** сразу.

1. Напишите мейнтейнеру через GitHub Security Advisory (вкладка
   **Security → Report a vulnerability**) или приватным сообщением.
2. Приложите версию (`uname -a` или `make version`), конфигурацию
   (`config/hix.conf`, параметры `hix.*`), шаги воспроизведения и лог COM1
   (`make run-serial`).
3. Дайте разумное время на исправление до публикации деталей.

Если приватный канал недоступен, откройте issue без эксплойта и попросите
связаться privately.

## Что считается уязвимостью

- Побег из ring 3: программа из `/bin` получает доступ к памяти ядра,
  меняет чужие процессы или выполняет привилегированные инструкции.
- Обход `qubix_user_range_ok`/`copy_str`: ядро читает или пишет по
  пользовательскому указателю без проверки адресного пространства.
- Порча кучи/стека ядра, double free, переполнение буфера из данных
  пользователя.
- Ошибка в `SYS_crypto`: утечка ключа, принятие подделанного тега,
  переполнение при копировании AAD/данных.
- Загрузочная строка `hix.*`, которая ломает инварианты безопасности
  (например, отключает проверку указателей).

## Что не считается уязвимостью

- Отсутствие изоляции пользователей, прав файлов, ASLR, NX для ring 3 в
  полном объёме или защиты от физического доступа.
- Паника ядра при заведомо некорректном образе/железе без сценария
  эксплуатации.
- `crash`, `panic`, `halt` и `reboot` из шелла: это документированные
  команды для отладки.
- Ограничения, перечисленные в [docs/VERSIONING.md](docs/VERSIONING.md) и
  [README.md](README.md).

## Криптография

Rust-модуль `rust/hix-core` реализует ChaCha20-Poly1305 (RFC 8439) и
проверяется unit-тестами, Python-эталоном и `cryptotest`. Он не заменяет
аудит: если вы используете hix для реальных секретов, считайте модуль
демонстрацией ABI, а не проверенной библиотекой. Ключи копируются в память
ядра, затираются после вызова; пользовательские указатели проверяются до
копирования. Подробности — [docs/CRYPTO.md](docs/CRYPTO.md).

## Релизы

Контрольные суммы публикуются в `SHA256SUMS`. Проверяйте их перед запуском
скачанного `hix.elf`/`hix.iso`. Процесс сборки и публикации описан в
[docs/RELEASE.md](docs/RELEASE.md).
